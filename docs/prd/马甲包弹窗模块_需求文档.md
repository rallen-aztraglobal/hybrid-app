# 马甲包弹窗模块 — 需求文档

| 项 | 内容 |
|---|---|
| 版本 | v1.3（定稿） |
| 日期 | 2026-09-24 |
| 状态 | 已定稿，变更须更新 §12 |
| 范围 | 马甲包客户端弹窗展示与埋点、后台配置项定义 |
| 不在范围 | 接口参数定义（另行约定）、H5 内部弹窗 |

---

## 1. 目标

让运营可以在后台自行配置弹窗内容与图片，不依赖发版；并能看到每个弹窗的展示率与点击率，用于判断素材和频控是否合理。

本文档**列出全部合理的弹窗位置**，实际开哪几个由业务侧按优先级决定，客户端按统一框架实现，位置通过配置开关控制。

---

## 2. 弹窗位置清单

| # | 位置 | 形态 | 适用场景 | 可关闭 | 支持轮播 | 建议优先级 |
|---|---|---|---|---|---|---|
| P1 | 启动弹窗 | 遮罩 + 居中卡片 | 活动、首存、节日推广 | 是 | ✅ | **P0** |
| P2 | 悬浮球 | 常驻浮标，可拖动 | 长期活动入口、客服 | 是 | ❌ | **P0** |
| P3 | 底部横幅 | 贴底条幅 | 长期挂的次要活动 | 是 | ✅ | P1 |
| P4 | 更新 / 公告提示 | 遮罩 + 居中卡片 | 换包、换域名、维护通知 | 可配置 | ❌ | P1 |
| P5 | 顶部通栏 | 贴顶细条 | 维护公告、系统提示 | 是 | ❌ | P2 |
| P6 | 退出挽留 | 返回键拦截弹窗 | 挽留、优惠券 | 是 | ❌ | P2 |
| P7 | 全屏插屏 | 整屏图片 | 大型活动、开屏广告 | 是 | ✅ | P2 |
| P8 | 便条 | 贴边扁条，高约 28dp | 关闭后的找回入口 / 常驻曝光位 | 长按 | ❌ | **P0** |

### P1 启动弹窗

冷启动或从后台回到前台（间隔 > N 分钟）时触发。半透明遮罩 + 居中图片卡片 + CTA 按钮 + 右上角关闭。支持多张轮播，左右滑动切换，底部圆点指示。

**主力位置。** 曝光最高、干扰也最大，频控必须严格。

### P2 悬浮球

常驻在 WebView 之上的小浮标，可拖动、可手动关闭（关闭后当次会话不再出现）。支持红点角标。

干扰最小、生命周期最长，适合放长期活动入口。不做轮播——轮播的浮标会让用户无法预期点击后去哪。

### P3 底部横幅

贴底条幅，含小图标 / 缩略图 + 一行文案 + 关闭按钮。不遮挡主内容。支持多条轮播（自动切换，间隔可配）。

需注意与 H5 自身底部导航的遮挡关系，建议预留安全距离或由 H5 侧让出高度。

### P4 更新 / 公告提示

马甲包特有场景：通知用户换包、换域名、系统维护。形态与启动弹窗一致，但：

- 可配置为**不可关闭**（强制模式），此时无关闭按钮、遮罩点击无效
- 强制模式仅用于"不换包就不能用"的情况，**日常活动严禁使用**
- 需支持"跳转外部链接 / 应用商店"的按钮行为

### P5 顶部通栏

贴顶的细条，纯文字 + 关闭。适合维护公告、系统级提示。不放营销内容。

### P6 退出挽留

拦截返回键，在用户准备退出时弹出。形态同启动弹窗。

**每次会话最多一次**，第二次返回直接退出——否则用户会退不出去，这是差评和卸载的高发点。

### P7 全屏插屏

整屏图片，右上角关闭（建议延迟 0 秒即可见，见 §8）。视觉冲击最强、干扰也最强。

建议只在大型活动期间临时开启，且与启动弹窗互斥。

### P8 便条

贴屏幕右侧边缘的扁条，高约 28dp，含小图标 + 一行极短文案（建议 ≤ 5 字）。半透明，不占据角落方块面积，视觉重量低于悬浮球。

**两态：**

- **展开态**：图标 + 文案，宽约 90–110dp
- **收缩态**：静止 3 秒后横向收缩，只保留图标（约 32dp 宽），进一步降低不透明度；用户点击或页面滚动停止后恢复展开态

**常驻。** 便条是本模块唯一的长期曝光位，不设自动消失。它承担两个角色：

1. 弹窗关闭后的找回入口
2. 独立的常驻活动入口——这部分曝光与点击属于自有库存，数据须留在客户端侧统计

**位置约束**：垂直方向避开 H5 底部导航与充值 / 下单等关键操作区，建议锚定屏幕右侧中下部（距底部约 25% 屏高），并预留底部安全区。

**单点 = 展开，长按 = 彻底关闭。** 这一条是便条能不能成立的关键——如果单点就能关掉，用户手滑一次内容就永久消失了，等于没解决找回问题。长按需给出确认反馈（震动或提示"本日不再显示"）。

### 关闭降级机制

适用于 P1 / P3 / P4（非强制模式）/ P7。

用户关闭弹窗时，**默认不是直接消失，而是收起为便条**：

```
弹窗展示中
    ↓ 点关闭
收起为便条（贴边、半透明、常驻）
    ↓ 单点              ↓ 长按
重新展开弹窗          彻底关闭（当日不再出现）
```

这解决了原设计的一个缺口：用户随手关掉后想再找回来，此前没有任何入口。同时它还有个副作用——**关闭不再等于流失**，运营可以从"找回率"看出素材是真的没吸引力，还是只是弹出时机不对。

若某个弹窗不需要便条态（例如纯公告类），后台可关闭该弹窗的便条开关，此时关闭即消失。

---

### 倒计时关闭

适用于大型弹窗 P1 / P7（P4 强制模式除外，P3 / P5 / P6 不适用）。

关闭按钮延迟 3 秒后可用，用于保证素材最低曝光时长。实现须满足以下全部约束：

| # | 约束 | 原因 |
|---|---|---|
| 1 | 倒计时数字从第 0 秒起就显示在关闭按钮位置 | 留空位再突然出现 X，会被判定为隐藏关闭入口；显示倒计时是行业通行做法，风险低得多 |
| 2 | 倒计时上限硬编码为 3 秒，后台只能开 / 关，不能调数值 | 可调必然被拉长 |
| 3 | **Android 返回键全程可关闭，不受倒计时限制** | 这是最关键的一条。挡住返回键才是真正引发用户投诉和商店申诉的行为 |
| 4 | 倒计时结束后 X 需放大到正常尺寸，热区 ≥ 44×44 dp | 小 X 会被判为诱导点击 |
| 5 | 遮罩点击在倒计时期间无效，结束后按配置生效 | 行为一致 |
| 6 | 弹窗被切到后台时倒计时暂停，回前台续计 | 避免用户切走再回来仍被卡住 |

> 延迟关闭本身是常见做法（开屏、插屏广告普遍如此），但它确实处在应用商店"干扰性广告"政策的关注范围内。上面 6 条里，**第 1 条和第 3 条是把风险压到最低的关键**：倒计时可见 + 返回键可退，意味着用户任何时候都有明确的退出路径，这与"无法关闭的全屏广告"有本质区别。建议不要为任何活动突破 3 秒。

## 3. 轮播规则

适用于 P1 / P3 / P7。

| 项 | 规则 |
|---|---|
| 张数 | 建议上限 5 张，超出后台不允许保存 |
| 顺序 | 按后台配置的排序字段 |
| 切换 | 手动左右滑动；P3 支持自动轮播（间隔可配，默认 5s） |
| 指示器 | 底部圆点，当前页高亮 |
| 单张时 | 隐藏圆点，禁用滑动 |
| **埋点** | **按卡片级记录**，滑到且停留 ≥ 1s 才计一次曝光 |

> 轮播的核心价值是让运营能同时推多个活动而不必连弹。但如果统计只按弹窗级记，第 2、3 张的点击率分母会虚高，数据会直接误导素材决策——**卡片级曝光是这个功能的前提，不是优化项**。

## 4. 触发与频控

### 4.1 触发时机

| 位置 | 触发时机 |
|---|---|
| P1 | 冷启动；或回前台且距上次活跃 > 30 分钟（可配） |
| P2 | WebView 首屏加载完成后 |
| P3 / P5 | WebView 首屏加载完成后 |
| P4 | 冷启动，优先级高于 P1 |
| P6 | 用户按返回键且当前为首页 |
| P7 | 冷启动，与 P1 互斥 |

### 4.2 频控规则（写死在代码，不做后台配置）

频控以常量形式固化在客户端，**后台不提供频控配置入口**。理由：频控一旦可配，运营会持续承受"这次活动重要，今天多弹两次"的压力，最终必然放宽到伤害留存；且各活动频控不一致会让展示率完全不可横向比较。

| 位置 | 每日上限 | 关闭后行为 | 会话内 |
|---|---|---|---|
| P1 启动弹窗 | 1 次 | 收起为便条，当日不再自动弹 | — |
| P2 悬浮球 | 常驻 | 当次会话不再出现 | — |
| P3 底部横幅 | 常驻 | 收起为便条，24h 内不再自动出现 | — |
| P4 更新 / 公告（普通） | 1 次 | 收起为便条 | — |
| P4 更新 / 公告（强制） | 每次冷启动 | 不可关闭 | — |
| P5 顶部通栏 | 常驻 | 当日不再出现 | — |
| P6 退出挽留 | 1 次 | 直接消失 | 每会话最多 1 次 |
| P7 全屏插屏 | 1 次 | 收起为便条，当日不再自动弹 | — |
| P8 便条 | 常驻 | 长按关闭后当日不再出现 | — |

轮播弹窗按**整个弹窗**计频控，不按卡片计——一次展示滑几张都算一次。

> **后台必须保留的是"开关"，不是频控。** 素材配错、活动提前结束、图片违规，这些情况必须能立刻停掉，不能等发版。开关与频控是两件事：开关决定"还要不要投"，频控决定"投的时候多久一次"，前者属于运营、后者属于产品。
>
> 代价要知道：频控写死后若数值定错，改动需要发版。马甲包发版意味着重新上架和用户更新，周期以周计。因此上线前建议先按上表跑两周，用 §7.2 的拦截分布验证一次再固化。

### 4.3 互斥与优先级

- 同一时刻**只允许一个遮罩类弹窗**（P1 / P4 / P6 / P7）
- 多个同时命中时，按后台优先级取最高的一个展示，其余记为"被互斥拦截"
- 非遮罩类（P2 / P3 / P5）可与遮罩类共存，但需在遮罩之下
- Native 弹窗展示期间，需告知 H5 暂停其自身弹窗（避免叠加）

## 5. 状态流转

```
App 启动 / 回前台
      ↓
读取弹窗配置（后台下发，本地有缓存）
      ↓
定向过滤 ──不匹配──→ 结束
（palcode / 包 / 版本 / 新老用户）
      ↓
时间过滤 ──不在生效期──→ 结束
      ↓
频控判定 ──超限──→ 记 filtered（原因：频控）→ 结束
      ↓
互斥判定 ──被更高优先级占用──→ 记 filtered（原因：互斥）→ 结束
      ↓
记 trigger
      ↓
图片预加载 ──失败/超时──→ 记 load_fail → 不展示 → 结束
      ↓
展示 → 记 impression（轮播按卡片）
      │
      ├─ 开启倒计时时：显示倒计时数字，3s 后 X 可点（返回键全程可关）
      ↓
   ┌──点击 CTA──→ 记 click → 跳转 → 写频控
   ├──滑动──────→ 记 slide → 新卡片记 impression
   └──关闭──────→ 记 close → 写频控
                      ↓
              启用便条态？──否──→ 结束
                      ↓ 是
              记 collapse → 生成便条 → 记 tab_impression
                      ↓
                 ┌──单点──→ 记 tab_click → 重新展示弹窗（不重复计频控）
                 └──长按──→ 记 tab_dismiss → 当日不再出现
```

## 6. 后台配置项

### 素材

- 图片（建议固定比例，P1 推荐 3:4，P7 推荐 9:16）
- 跳转链接
- 按钮文案（可选，留空则整图可点）
- 标题 / 描述文案（可选）
- 排序（轮播顺序）

### 投放

- 弹窗位置（P1–P7）
- 生效开始 / 结束时间
- 优先级
- 开关

### 定向

- palcode / 包（多选，默认全部）
- App 版本（大于等于 / 小于）
- 新老用户
- 地区（如可获取）

### 频控

**不提供配置。** 频控写死在客户端，见 §4.2。运营侧只通过"开关"控制某个弹窗是否投放。

### 行为

- 是否启用便条态（关闭后收起为便条 / 关闭即消失）
- 便条图标与文案
- 是否启用倒计时关闭（仅 P1 / P7，开或关，时长固定 3 秒不可调）
- 遮罩点击是否关闭
- 是否可关闭（仅 P4 可设为否）
- 跳转方式（WebView 内 / 外部浏览器 / 应用商店）

### 生效机制

配置改动**不需要重新打包**，但需明确"多久生效"与"为什么可能不生效"。

**拉取时机**

| 时机 | 说明 |
|---|---|
| 冷启动 | 必拉 |
| 回前台 | 距上次拉取 > 5 分钟则重拉 |
| 兜底 | 拉取失败用本地缓存配置；无缓存则本次不展示任何弹窗 |

最坏情况下的生效延迟 = 用户下次回前台。**后台需在编辑页明示这一点**，避免运营改完立刻看手机发现没变，以为是 bug。

**换图必须换 URL —— 这是最容易翻车的一条**

同一个 URL 换图，会被两层缓存挡住：CDN 边缘缓存 + 客户端磁盘缓存。结果是运营在后台看到新图、用户手机上还是老图，且可能持续数天。

要求：

- 后台上传新图时**必须生成新文件名**（加内容 hash 或时间戳），不允许覆盖同名文件
- 客户端磁盘缓存以完整 URL 为 key，URL 变了自然重新下载
- 配置携带 `config_version`，版本变化时清理已不在配置中的素材缓存

**素材预热**

拉到新配置后立即在后台线程预下载所有图片。否则首次展示时才下载，很容易触发 §9 的"预加载失败 → 不展示"，表现为配置生效了但弹窗不出现。

**紧急下线**

后台关闭开关后，按上述拉取时机生效（最慢约 5 分钟 + 用户切换动作）。若业务上需要更快（如素材违规需立即撤下），需另行增加服务端推送能力，本期不含。

### 可配置边界

| 随时改、立即按上述机制生效 | 需要发版 |
|---|---|
| 图片、文案、跳转链接 | 频控数值（§4.2） |
| 轮播卡片增删与排序 | 倒计时时长（固定 3 秒） |
| 生效时间段 | 便条尺寸、位置、两态切换逻辑 |
| 定向条件（palcode / 版本 / 新老用户） | 弹窗位置的形态与交互 |
| 各位置开关、单个弹窗开关 | 新增位置类型 |
| 优先级 | 埋点事件定义 |
| 便条图标与文案 | — |
| 倒计时开 / 关 | — |

> 运营日常需要改的都在左列。右列是产品与体验的底线，改动需走发版——这正是把频控和倒计时时长写死的目的。

## 7. 数据与埋点

### 7.1 埋点事件

| 事件 | 触发时机 | 需区分维度 |
|---|---|---|
| `popup_trigger` | 通过所有过滤、准备展示 | 弹窗 ID、位置 |
| `popup_filtered` | 被拦截未展示 | 拦截原因（频控 / 互斥 / 定向 / 时间） |
| `popup_load_fail` | 图片预加载失败或超时 | 弹窗 ID |
| `popup_impression` | 真实渲染完成 | **卡片 ID**、轮播序号 |
| `popup_click` | CTA 或整图被点击 | 卡片 ID |
| `popup_close` | 关闭按钮 / 遮罩 / 返回键关闭 | 关闭方式 |
| `popup_collapse` | 关闭后收起为便条 | 弹窗 ID |
| `tab_impression` | 便条渲染完成 | 弹窗 ID |
| `tab_click` | 便条被单点展开 | 弹窗 ID |
| `tab_dismiss` | 便条被长按彻底关闭 | 弹窗 ID |
| `popup_slide` | 轮播切换 | 从第几张到第几张 |

所有事件需带：palcode、包名、App 版本、时间戳。

### 7.2 指标口径

| 指标 | 公式 | 看什么 |
|---|---|---|
| 展示率 | 曝光 / 触发 | 低 → 预加载失败或频控设太紧 |
| 点击率 | 点击 / 曝光 | 低 → 素材或文案问题 |
| 关闭率 | 关闭 / 曝光 | 高 → 内容与用户预期不符 |
| 加载失败率 | load_fail / 触发 | 高 → 图片太大或 CDN 有问题 |
| 轮播深度 | 平均滑到第几张 | 低 → 第 2 张之后基本没人看，别配太多 |
| 找回率 | 便条展开 / 收起为便条 | 高 → 内容有价值但弹出时机不对，该调触发而非换图 |
| 便条弃用率 | 长按关闭 / 便条曝光 | 高 → 便条本身构成干扰，该缩小或换位置 |
| 总点击率 | （弹窗点击 + 便条点击）/ 曝光 | 便条带来的增量，用来判断这个机制值不值得留 |
| 拦截分布 | filtered 按原因分组 | 看频控是不是卡太死 |

> 展示率和点击率要分开看。展示率低是**工程问题**，点击率低是**素材问题**，混在一起会让运营反复换图却没用。

### 7.3 埋点可靠性

- 埋点需本地缓存 + 失败重试。弹窗曝光集中在冷启动那几秒，正是网络最不稳定的时候，不做缓存会导致展示率系统性偏低。
- 同一次展示的 impression 需去重，避免页面重绘造成重复计数。

## 8. 交互与合规细则

| # | 规则 | 原因 |
|---|---|---|
| 1 | 关闭入口全程可见：无倒计时则 X 即时可见，有倒计时则显示倒计时数字，**不得留空位** | 隐藏关闭入口是应用商店明确关注项 |
| 2 | 返回键全程可关闭，不受倒计时限制（P4 强制模式除外） | 保证任何时候都有退出路径 |
| 3 | 关闭按钮点击热区 ≥ 44×44 dp | 太小会被判为诱导点击 |
| 4 | 除 P4 强制模式外，所有弹窗必须可关闭 | 同上 |
| 5 | 不得自动跳转外部应用或商店，必须用户主动点击 | 同上 |
| 6 | P6 每次会话最多拦截一次返回键 | 否则用户退不出去 |
| 7 | 便条不得遮挡 H5 充值 / 下单 / 提交类按钮 | 遮挡转化按钮会直接损失业务 |
| 8 | 弹窗展示不阻塞 WebView 加载 | 首屏体验 |
| 9 | 图片预加载超时上限 3 秒 | 超时就放弃，别让用户等 |

## 9. 异常与边界

| 场景 | 处理 |
|---|---|
| 配置拉取失败 | 使用本地缓存配置；无缓存则静默跳过 |
| 配置为空 | 静默跳过，不记任何事件 |
| 新配置素材尚未预热完成 | 本次沿用上一份已预热的配置，下次拉取后切换 |
| 素材 URL 变更但旧图仍在缓存 | 以 URL 为缓存 key，旧图不复用；`config_version` 变化时清理失效素材 |
| 图片加载失败 | 不展示、不计曝光、记 `load_fail` |
| 跳转链接为空或非法 | 整图不可点，仅可关闭 |
| 多弹窗同时命中 | 按优先级取一个，其余记 `filtered` |
| 弹窗展示时 App 被切到后台 | 回前台时保持展示，不重复记曝光 |
| H5 同时有弹窗 | Native 弹窗展示期间通知 H5 挂起 |
| 低版本 App 收到新位置配置 | 忽略未知位置，不崩溃 |

## 10. 验收

- [ ] 各位置可通过后台开关独立启用 / 关闭，关闭后完全不触发
- [ ] 图片、链接、文案改动后台生效，无需发版
- [ ] 后台改动后，冷启动或回前台超 5 分钟即可拉到新配置
- [ ] 后台上传同名图片被拒绝，新图生成新文件名
- [ ] 换图后客户端展示新图，不受磁盘缓存影响
- [ ] 拉到新配置后素材完成预热，首次展示不因下载失败被跳过
- [ ] 配置拉取失败时使用本地缓存，不崩溃、不展示空白弹窗
- [ ] 轮播按卡片记曝光，滑动到第 2 张才产生第 2 张的曝光
- [ ] 频控生效：P1 当日第二次启动不再弹出，且记录 `filtered`
- [ ] 关闭弹窗后收起为便条，单点可重新展开，长按才彻底关闭
- [ ] 便条长按关闭后，当日不再出现便条与该弹窗
- [ ] 关闭便条态开关的弹窗，关闭后直接消失、不生成便条
- [ ] 便条不遮挡 H5 关键操作区域（下单 / 充值按钮）
- [ ] 后台开关关闭后，弹窗与其便条同时立即停止出现
- [ ] 多弹窗命中时只展示优先级最高的一个
- [ ] 图片加载失败时不展示且不计曝光
- [ ] 无倒计时的弹窗，关闭按钮即时可见，热区达标
- [ ] 开启倒计时的弹窗，倒计时数字从第 0 秒即显示，3 秒后 X 放大可点
- [ ] 倒计时期间按返回键可立即关闭弹窗
- [ ] 弹窗切后台再回前台，倒计时续计而非重置
- [ ] P6 连续按两次返回可正常退出
- [ ] 断网状态下启动不崩溃，埋点进入缓存队列，恢复网络后补传
- [ ] 后台可看到每个弹窗 / 每张卡片的触发、曝光、点击、展示率、点击率
- [ ] 弹窗展示不影响 WebView 首屏加载耗时

## 11. 决策项与默认取值

以下为实现前必须确定的项。**每项已给出默认取值，未另行通知即按默认实现**，不得自行选择其他方案。

| # | 事项 | 默认取值 | 若要改动 |
|---|---|---|---|
| 1 | 首批开启的位置 | P1 启动弹窗、P2 悬浮球、P8 便条；其余位置代码实现但默认关闭 | 后台开关即可，无需改码 |
| 2 | 频控记录归属 | 按设备（未登录状态无 user_id）；登录后若与服务端记录冲突，取更严格的一方 | 需产品确认 |
| 3 | 「每日」重置时机 | 以服务端时间为准；服务端不可用时用本地时间，并检测时间跳变，跳变超 2 小时视为作弊不重置 | 不建议改 |
| 4 | 同时存在的便条数量 | 最多 2 条，超出时替换最旧的一条 | 需产品确认 |

| 6 | P7 是否默认开倒计时 | 默认开启 | 后台开关即可 |
| 7 | 新老用户判定 | 由客户端按「是否存在本地首次启动记录」判定；H5 提供更准确判定后改用 H5 口径 | 需 H5 配合 |
| 8 | 图片托管 | 走 CDN；客户端按 URL 加载并做本地磁盘缓存 | 需后端确认 |
| 9 | P3 与 H5 底部导航的遮挡 | P3 默认关闭，启用前由 H5 让出对应高度 | 需 H5 配合 |
| 10 | 埋点上报通道 | 与现有回传链路共用；若不可用则独立上报 | 需后端确认 |
