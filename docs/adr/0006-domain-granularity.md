# ADR-0006: 域名配置粒度——大渠道默认 + 小渠道可覆盖

- **状态**：已采纳(2026-06-24)

## 背景
需求说「子渠道的包要可以配置 web 域名」。但现实里域名被封通常是**整个品牌一起换**（arenaplus.ph 挂了，所有 `ap` 渠道一起换），若只能逐个小渠道配置，换域名要改几十处。

## 决策
域名**优先在大渠道（品牌）级配置**（`brand_domain` 表，主 + 最多 3 备用），小渠道默认**继承**（`channel.use_brand_domains=1`）；个别需差异化时关闭继承、用 `channel_domain` 覆盖。

## 理由
- 贴合真实运维：换域名 = 改品牌一处，旗下所有渠道同时生效。
- 同时保留小渠道覆盖能力，满足需求字面要求。

## 后果
- ✅ 「换域名」成本最低；UI 域名页以品牌为主、渠道编辑里提供「继承/覆盖」开关。
- ➖ 取用时需合并继承逻辑：`GET /api/app/config` 按 `use_brand_domains` 决定取品牌还是渠道域名。

## 备选
- **仅小渠道级**：换域名要改 N 处，运维灾难，被否。
- **仅品牌级**：无法满足个别渠道差异化，被否。
