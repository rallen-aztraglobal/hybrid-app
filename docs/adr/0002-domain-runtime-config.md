# ADR-0002: 域名运行时下发 + 自更新缓存 + 编译期兜底

- **状态**：已采纳(2026-06-24)；**更正(2026-06-24, 见 ADR-0009)**：解析键由 PAL_CODE 改为 **applicationId**（PAL_CODE 跨品牌可重复、不唯一）。下文凡以「palcode」作解析键处，按 ADR-0009 读作 `appId`。

## 背景
业务域名（arenaplus.ph 等）经常被封、频繁更换。现状把域名写进 `BuildConfig`（编译期焊死），改域名必须重新打包并重新分发**所有**已发布渠道，代价极高。用户明确要求：**域名随时改、随时生效，不是打包时一次性的**。

## 决策
域名按三级取用，APK **每次启动调用一次** `GET /api/app/config?palcode=`：
1. **实时拉取成功** → 用返回清单，并**立即写入本地缓存**（覆盖旧值）。
2. **失败** → 用**本地缓存**（上一次成功返回的配置）。
3. **从未成功过**（首装即无网）→ 用编译期烧录的 `assets/bootstrap.json` 默认清单。

编译期只固定不变量：`PAL_CODE`（渠道身份）和配置服务地址。

## 理由
- 域名改动只需后台改一处，已安装包下次启动即生效，**无需重新打包**——直击「域名经常变」。
- 「兜底 = 最近一次成功的配置」，随每次成功拉取自更新，不停留在陈旧的打包快照。
- 短超时（0.8~1.5s）+ 缓存兜底，首屏不被接口拖慢。

## 后果
- ✅ 域名热更，运维成本骤降。
- ➖ 引入「配置端点高可用」新责任：端点须部署在**抗封基础设施**（CDN/对象存储静态 JSON，与业务域名分离），后台保存即生成快照。否则业务域名全封时也拿不到新域名。
- 需要 APK 端 `DomainResolver.loadDomainList()` 实现三级取用（见 docs/admin/02）。

## 备选
- **纯编译期**（现状）：改域名=重打全部包，被否。
- **纯运行时**（无编译期兜底）：首启无网即白屏，被否。
