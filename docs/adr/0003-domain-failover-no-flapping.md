# ADR-0003: 域名容灾——区分「域名故障」与「本机网络」，绝不乱换

- **状态**：已采纳(2026-06-24)

## 背景
APK 配主域名 + 最多 3 备用，主域名不通则切备用。用户**反复强调**：只有「域名本身出问题」才换域名；「本机网络问题」（没网/弱网/假 WiFi/门户认证）**绝不能乱换**——否则会把好域名挨个误判、浪费时间、给错误文案。

## 决策
实现状态机 `DomainResolver`（详见 docs/admin/02），关键是**双保险**：
- **STEP 0 本机网络闸门**：`ConnectivityManager` 无「已验证可上网」网络 → 直接「网络异常」，完全不碰域名。
- **STEP 2** 按序探测域名，且必须**校验「确实是我们的站点」**（业务特征 JSON + TLS 证书域名），防 ISP 劫持假 200。
- **STEP 3 中立连通性探针**裁决全失败的归因：请求 gstatic/cloudflare 的 `generate_204`（多端点任一成功即视为有公网）。
  - 中立点能通、我域名全挂 = **域名问题** → 已穷尽备用，提示「服务暂时不可用」+ 上报告警。
  - 中立点也不通 = **本机问题** → 提示「网络异常」，**不归咎域名**。
- 运行中容灾：`onReceivedError/onReceivedHttpError` **仅对主框架** + 防抖，避免子资源错误或抖动网络触发狂换。

## 理由
切换只发生在 STEP 2（且 STEP 0 已确保有网才会走到），全失败的文案由 STEP 3 中立探针决定，从机制上杜绝「本机断网→把备用域名全试一遍」的乱换。

## 后果
- ✅ 行为可预期：断网只提示、不乱换；域名真故障才切换。
- ➖ 多一次中立探针请求（仅全失败时，~2s）；需后端提供 `/healthz` 业务特征端点供校验。

## 备选
- **朴素「失败就试下一个」**：弱网下乱换、误判、体验差，被否。
- **只看 `ConnectivityManager.VALIDATED`**：不足以证明能访问公网/我们的站点（可能连了 WiFi 但无外网），故再加 STEP 3 中立探针。
