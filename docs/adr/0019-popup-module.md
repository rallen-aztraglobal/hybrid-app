# ADR-0019: 马甲包弹窗模块——后台只管开关与素材、频控写死客户端、埋点入库即按天聚合

- **状态**：提议
- **背景**：运营要在不发版的前提下给渠道 APK 配弹窗（启动弹窗、悬浮球、便条等 8 个位置），并看到每个弹窗 / 每张卡片的展示率与点击率（PRD：`docs/prd/马甲包弹窗模块_需求文档.md` v1.3）。约束：域名不得编译期焊死（ADR-0002）、身份键是 applicationId（ADR-0009）、后端 Go + MySQL 单机。
- **决策**：
  1. **配置**：后台存「位置开关 + 弹窗（投放/定向/行为）+ 素材卡片」，App 冷启动必拉 `GET /api/app/popups?appId=`、回前台 > 5 分钟重拉；品牌/包/地区定向在服务端过滤，版本/新老用户/生效时间在客户端过滤。
  2. **频控、倒计时时长、便条形态写死在客户端**，后台不提供入口；后台只保留「开关」（PRD §4.2）。
  3. **换图必须换 URL**：上传对象 key 恒为 `popup/images/<内容 hash>-<毫秒>.<ext>`，从不覆盖；客户端磁盘缓存以完整 URL 为 key。
  4. **埋点**：客户端本地持久化队列 + 批量上报 `POST /api/app/popups/events`，`batchId` 幂等；服务端**不落原始事件**，入库即按 `(日期, 弹窗, 卡片, 包, 版本, 事件, 维度)` 聚合累加到 `popup_stat_daily`。
  5. **客户端按弹窗粒度切换配置**：新配置中已移除的弹窗立即下线；新素材未预热完成的弹窗沿用上一份已就绪版本。
- **理由**：
  - 频控可配必然被运营压力逐步放宽、且让各活动展示率不可横向比较；开关属于运营、频控属于产品。
  - 统计只需计数与比率，聚合表行数 ≈ 弹窗数 × 卡片数 × 包数 × 天 × 事件，远小于原始事件量，单机 MySQL 直扛，无需引入队列/OLAP。
  - 地区定向要用请求 IP，必须服务端判；版本/新老用户只有客户端知道，且缓存配置在离线时也要正确判时间。
  - 「整份配置等预热完再切换」会让后台关开关的紧急下线被素材下载拖住；按弹窗粒度切换两头兼顾。
- **后果**：
  - 正面：改素材/开关/定向零发版；数据口径固定（事件定义写死）；同 URL 缓存翻车被结构性杜绝。
  - 负面：频控数值定错需发版（周期以周计），上线前按 PRD 建议先跑两周看拦截分布；聚合表无法回溯做 UV / 漏斗等原始事件分析；地区定向使配置端点不能走 CDN 共享缓存（`no-store`）。
  - 跟进：需要秒级紧急下线时另做服务端推送（本期不含）；H5 侧需监听 `hybrid:native-popup` 事件暂停自身弹窗。
- **备选**：
  - 原始事件入库再离线聚合：可做 UV/漏斗，但数据量大一个数量级、需要清理与分区策略，本期需求用不到 → 放弃。
  - 复用 AppsFlyer/Adjust 回传链路上报埋点：那是归因渠道，事件计费且口径不受控，便条/弹窗属于自有库存，数据须留在自己这边（PRD §2 P8）→ 放弃。
  - 客户端引入 Glide/Coil 做图片缓存：依赖重且缓存 key/清理策略不受控，自写 URL→文件的磁盘缓存足够 → 放弃。
